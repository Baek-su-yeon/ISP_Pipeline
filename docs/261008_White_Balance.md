## 요약

1단계 결과 `normImg`에 카메라 WB 계수를 Bayer 위치별로 곱해 `WBImg`(자르지 않음)와 `WBClip`(1로 자름)을 만들었다. a0001, a0005 두 장 모두 기대값과 일치해 2단계가 끝났다.

- **이득 표**: `gains[2][2]`를 반복문 밖에서 만들고, G2(LibRaw 번호 3)는 `cam_mul[1]`로 대체했다. `cam_mul[1]`로 나눠 G = 1 기준을 보장했다.
- **검증**: 채널별 평균 비율(WB 후 / 전)이 R·B 이득과 정확히 같았고, G\_R·G\_B 평균은 변하지 않았다. a0005의 자르지 않은 최댓값은 포화 R × R 이득인 2.05176이었다.
- **실험 3 근거 확인**: a0001은 WB 후에도 최댓값 0.976으로 1을 넘지 않는다. 포화+WB 실험은 a0005로 하는 게 맞다.
- **가장 많이 배운 것**: 표가 맞아도 반복문이 표를 맞게 썼는지는 따로 확인해야 한다. `wb / norm`과 채널 평균 비율로 "실제로 곱해진 이득"을 데이터에서 거꾸로 꺼내 확인했다.
- **코드**: `src/test.cpp`.

## 시작 전 정리

2단계 코드는 1단계 파일에 이어 썼다. 함수 분리는 계획대로 4단계 전후에 한다.

| 결정 | 이유 |
| --- | --- |
| 1단계 파일에 이어 쓰기 | 일정이 반나절 밀림. 인터페이스(메타데이터 구조체, 인자)는 Demosaic·감마까지 모양이 보인 뒤 정하는 게 덜 헤맨다. `normImg`를 같은 `main`에서 바로 넘겨받는다 |
| 1단계 비교 블록 제거 | `real.png`를 못 읽으면 `return 1`로 종료해, 0-2를 안 돌린 사진(a0192 등)은 2단계까지 못 간다. 1단계 검증은 끝났다 |
| `patternR`, `patternC`를 `int`로 | unsigned와 섞이면 `int`가 unsigned로 바뀐다. 3단계에서 `r - 1`이 −1이 되면 약 42억이 된다 |
| `printDiff` 함수는 남김 | 4단계 LibRaw 기준 이미지 비교에 다시 쓴다 |
| `idx` → `colorIdx`, `patIdx` | 같은 이름이 LibRaw 색 번호와 위치 패턴 칸 번호로 쓰였다 |

정리 중에 정규화 반복문까지 지웠다가 되살렸다. 지울 대상은 1단계를 **검증**하던 코드이고, **계산**하는 코드는 다음 단계의 입력이다. 0-3 정리 때 `colors` 표까지 지웠던 것과 같은 실수다.

범위는 줄이지 않기로 했다. 2·3·4단계 예상 시간이 합쳐 6\~8시간이라 오늘 안에 끝낼 수 있다. 회색 물체 R·G·B 확인은 감마 뒤 컬러 이미지에서 한다.

## 진행 순서

1단계처럼 2×2 표를 먼저 검증하고, 그다음 전체 이미지로 넓혔다.

1. 2×2 위치마다 `cam_mul[COLOR(r, c)]`를 출력 → G2 칸이 0으로 나와 3→1 대체가 필요함을 확인
2. `colorIdx`를 먼저 변수로 받고 3이면 1로 바꾼 뒤 `cam_mul`에서 찾음. 칸마다 `(COLOR 번호->읽은 인덱스)이득` 출력 → 기대값과 일치
3. 이득을 `cam_mul[1]`로 나눠 G = 1 기준 보장 (두 사진은 이미 1이라 결과 같음)
4. 정규화 반복문과 별도로 WB 반복문 작성. 반복문 안에서는 곱하기만 하고 자르지 않음
5. 반복문 뒤 `cv::min`으로 1에서 자른 `WBClip`을 새 Mat에 만듦
6. 왼쪽 위 2×2 화소의 `norm`, `wb`, `wb / norm` 출력
7. `WBClip`을 8비트로 `wb.png` 저장
8. `colors` 표로 4채널로 나눠 WB 전·후 채널별 평균 출력

## 겪은 버그와 해결

대부분 실행 전 리뷰에서 잡았다. 여러 개가 컴파일은 되면서 값만 틀리게 나오는 종류였다.

| 버그 | 결과가 맞아 보였나 | 원인 | 해결 |
| --- | --- | --- | --- |
| 정리 중 정규화 반복문 삭제 | 아니요. 입력이 없음 | 검증 코드와 계산 코드를 구분하지 않음 | 정규화 반복문 되살림 |
| G2 칸 이득 0 | 아니요. 출력에 0 | `cam_mul[3]`은 "G와 같음"을 뜻하는 0 | `colorIdx`가 3이면 1로 바꾼 뒤 찾기 |
| `int gains[2][2]` | **예** | `cam_mul`은 실수. 2.129가 2로 조용히 잘림 | `float` |
| `normImg[r][c]` | 아니요. 컴파일 에러 | `cv::Mat`은 `[r][c]` 접근 불가 | `.at<float>(r, c)` |
| WB 반복문 안에서 `std::clamp` | **예** | 잘리지 않은 값이 사라져 a0005 최댓값이 1로 나옴. 실험 3 비교 불가 | 반복문 안에서는 곱하기만 |
| `wb`를 계산만 하고 저장 안 함 | 아니요. 전부 0 | `WBImg.at<float>()`에 대입 누락 | 대입 추가 |
| `cv::min(WBImg, 1.0f, WBImg)` | **예** | 결과를 자기 자신에 덮어써 원본 소실 | 새 Mat `WBClip`에 |
| 2×2 확인에 `norm / wb` | 아니요. 역수(0.646)가 나옴 | 나누는 순서 반대 | `wb / norm` |
| 2×2 확인을 `WBClip`으로 | **예** | 1을 넘는 화소면 비율이 이득보다 작게 나옴 | `WBImg`로 |
| 채널 Mat `CV_8UC1`에 `.at<float>` | 실행 시 엉뚱한 값 또는 종료 | 1바이트 칸에 4바이트를 씀. Mat 밖 메모리까지 덮어씀 | `CV_32F` |
| 채널 평균을 `WBClip`으로 | **예** (a0005) | 포화 R이 잘려 평균 비율이 이득보다 작아짐 | `WBImg`로 |
| `min/max` 출력 세 줄 형식 동일 | — | 어느 줄이 어느 이미지인지 구분 불가 | `norm`, `WB raw`, `WB clip` 이름 붙임 |

**이 확인으로 못 잡는 실수**: a0001은 대각선이 아닌 두 칸 이득이 모두 1이라 `gains[c % 2][r % 2]`처럼 행·열을 바꿔도 결과가 같다. a0005 여백(12, 74)도 둘 다 짝수라 실수로 더해도 2×2 위치가 바뀌지 않는다. 그래서 `wb / norm`과 채널 평균 비율을 함께 봤다.

## 검증 결과

두 사진 모두 기대값과 일치했다. 각 채널의 모든 화소에 같은 이득을 곱했으므로 평균 비율이 이득과 정확히 같아야 한다.

| 확인 | a0001 (BGGR) | a0005 (RGGB) | 판정 |
| --- | --- | --- | --- |
| 이득 표 `(COLOR->인덱스)이득` | `(2->2)1.547 (3->1)1 / (1->1)1 (0->0)2.129` | `(0->0)2.052 (1->1)1 / (3->1)1 (2->2)1.371` | 일치 |
| 왼쪽 위 2×2 `wb / norm` | 1.547 1 / 1 2.129 | 2.052 1 / 1 1.371 | 일치 |
| R 평균 (전 → 후) | 0.1157 → 0.2464 (×2.129) | 0.0786 → 0.1612 (×2.052) | 일치 |
| B 평균 (전 → 후) | 0.1303 → 0.2015 (×1.547) | 0.1267 → 0.1738 (×1.371) | 일치 |
| G\_R, G\_B 평균 | 0.2057, 0.2046 그대로 | 0.1400, 0.1402 그대로 | G2 대체가 반복문에서도 맞음 |
| norm 최댓값 | 0.933089 | 1 | 1단계와 같음 |
| WB 자르지 않은 최댓값 | 0.975721 | 2.05176 | a0005는 포화 R × R 이득 |
| WB 자른 최댓값 | 0.975721 | 1 | 정상 |

- **채널 균형**: WB 전에는 R·B가 G의 절반 정도였다. 후에는 a0001이 R 0.25 / G 0.21 / B 0.20, a0005가 R 0.16 / G 0.14 / B 0.17로 비슷해졌다. a0001의 R이 조금 높은 건 붉은 바위산 장면과 맞는 방향이다.
- **a0001은 WB 후에도 1을 넘지 않는다**: 처음 기대값을 "1\~1.99 사이"로 적었는데, 정확한 범위는 "1.99 이하"였다. a0001은 `WBImg`와 `WBClip`이 같다.
- **아직 컬러로 보지 않았다**: `wb.png`는 Bayer 흑백이다. 색이 맞는지는 Demosaic과 감마 뒤에 판단하고, 회색 물체 R·G·B 평균도 그때 확인한다.

## 질문하며 정리한 개념

### 왜 int로 바꾸나

`int`와 `unsigned`가 한 식에 섞이면 C++은 `int`를 `unsigned`로 바꿔 계산한다. 지금은 `r`, `c`가 0 이상이라 결과가 같지만, 3단계에서 이웃을 보려고 `r - 1`을 쓰면 첫 행에서 −1이 약 42억이 된다. 원칙: LibRaw의 unsigned 값은 받자마자 `int`로 바꾸고, 계산은 `int`나 `float`끼리 한다.

### gains 표의 역할

`bases`와 같은 구조의 위치별 WB 이득 표다.

|  | `bases[2][2]` (1단계) | `gains[2][2]` (2단계) |
| --- | --- | --- |
| 담는 것 | 위치별 기준값 (뺄 값) | 위치별 이득 (곱할 값) |
| 반복문 안에서 | `raw − bases[r % 2][c % 2]` | `norm × gains[r % 2][c % 2]` |

- `COLOR()`를 화소마다 부르지 않는다.
- G2의 3→1 대체를 표를 만들 때 한 번만 처리한다. 반복문 안에는 예외 처리가 없어 실수할 곳이 줄고, 표만 출력하면 대체가 맞는지 확인된다.

### cam\_mul과 cblack의 차이

|  | `cblack` (+ `black`) | `cam_mul` |
| --- | --- | --- |
| 연산 | 빼는 값 | 곱하는 값 |
| 단위 | raw 정수 (127, 1024 등) | 단위 없는 비율 (G = 1 기준 실수) |
| 원인 | 센서 회로가 빛과 무관하게 더해 둔 값 | 촬영 당시 조명의 색 |
| 바뀌는 단위 | 카메라마다 거의 고정 | 사진마다 다름 |
| 찾는 번호 | LibRaw 색 번호 + 위치 패턴 (`[4]` 이후) | LibRaw 색 번호만 |
| G2 (번호 3) | 실제 값 → 그대로 사용 | 0 = "G와 같음" → `cam_mul[1]` 사용 |

G2 처리가 반대인 이유: `cblack[3]`은 G와 다를 수 있는 실제 값이고(a0053은 G 1023, G2 1024), `cam_mul[3]`의 0은 값이 없다는 표시다.

순서는 빼고 나서 곱한다. 이득은 빛 신호에만 곱해야 한다. 기준값이 남아 있으면 빛과 무관한 값까지 증폭돼 어두운 곳에 색이 낀다(실험 2에서 볼 현상).

### cam\_mul\[1\]로 나누는 이유

WB에서 중요한 건 이득의 비율이다. `cam_mul`이 G = 1로 저장된다는 보장은 없다. 어떤 카메라가 `R 4.258, G 2, B 3.094`로 저장했다면 비율은 a0001과 같지만, 그대로 곱하면 모든 화소가 2배 밝아지고 G도 바뀐다. 각 이득을 `cam_mul[1]`로 나누면 어떤 카메라든 G = 1인 상대값이 된다. a0001, a0005는 이미 1이라 결과가 같다.

### 정규화와 WB 반복문을 나눈 이유

WB 전(`normImg`)과 후(`WBImg`)를 비교하려면 "전" 값이 남아 있어야 한다. 정규화 반복문 안에서 바로 곱하면 `normImg`에 이미 곱해진 값만 남는다. 4단계 뒤 함수로 나눌 때도 단계 경계가 이미 나뉘어 있다.

### wb / norm을 보는 이유

이득 표 출력은 "표가 맞다"는 확인이고, "반복문이 그 표를 맞는 화소에 썼다"는 확인은 아니다. `wb / norm`은 실제로 곱해진 이득을 결과 데이터에서 거꾸로 꺼낸 값이다. 1단계에서 패턴 값 대신 인덱스(`6 + idx`)를 출력한 것과 같은 방식이다.

### 자르지 않은 값과 자른 값

`WBImg`는 1을 넘는 값을 그대로 두고, `WBClip`은 반복문 뒤 `cv::min(WBImg, 1.0f, WBClip)`으로 만든다. 배열 두 개를 반복문 안에서 따로 채울 필요가 없다. 실험 3에서 "1에서 자름"과 "자르지 않고 축소"를 비교할 때 `WBImg`가 원본이다.

## 배운 점과 다음 단계

**배운 점**

- 표가 맞는 것과 반복문이 표를 맞게 쓴 것은 별개다. 결과 데이터에서 실제로 곱해진 값을 거꾸로 꺼내 확인한다.
- 같은 배열의 같은 번호 3이라도 의미가 다르다. `cblack[3]`은 실제 값, `cam_mul[3]`의 0은 "G와 같음"이다.
- 실험에 쓸 원본(자르지 않은 값)은 처음부터 남겨 두도록 짠다. 자르는 순간 되돌릴 수 없다.
- Mat의 타입과 `.at<T>`의 타입은 반드시 같아야 한다. 크기가 다르면 다른 메모리를 덮어쓴다.
- 기대값을 계산으로 먼저 적는 방식이 이번에도 통했다. 다만 기대값 자체도 틀릴 수 있다(a0001 최댓값 범위).
