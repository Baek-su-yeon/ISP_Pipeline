# 261005 0-1 메타데이터 검증 회고

## 요약

a0001 메타데이터를 raw-identify로 대조해 모두 일치함을 확인했고, 11장 전체를 출력해 비교했다. 그 과정에서 Black Level이 두 가지 방식으로 저장된다는 것을 알게 돼, 출력 코드를 두 번 고쳤다.

- **결과**: Nikon 3장은 Black 0·여백 0, Canon 8장은 Black 127 \~ 1024·여백 있음. White Level은 대부분 2ⁿ − 1이 아니었다.
- **결정**: 두 번째 개발 사진은 a0005, 실험 2는 시뮬레이션 없이 a0078로 한다.
- **코드**: `src/file_open.cpp`의 Black Level 출력부만 고쳤다. 여러 장 처리는 코드 대신 셸 반복문으로 했다.
- 값별 해석은 별도 문서 "FiveK 11장 메타데이터 해석"에 정리했다.

## 코드 변경 이력

모든 변경은 "Black Level을 빠짐없이, 사진마다 다른 형식에 맞게 출력한다"는 한 가지 목적에서 나왔다.

| 순서 | 변경 | 이유 |
| --- | --- | --- |
| 1 | `cblack` 출력 범위 `[0..3]` → `[0..5]` | DNG는 Black Level을 위치 패턴으로 저장할 수 있고, 그 크기가 `[4]`, `[5]`에 들어 있다 |
| 2 | `[0..3]`과 패턴 출력을 분리. 패턴은 `cblack[6]`부터 `6 + cblack[4] × cblack[5]` 직전까지 출력 | `[5]`까지만 출력하면 실제 값이 있는 `cblack[6]`이 빠진다. 값 개수는 패턴 크기에 따라 달라서 고정하지 않았다 |
| 3 | 변수 이름 `pattern_size` → `pattern_end` | 값이 패턴 크기(1)가 아니라 반복문이 멈출 인덱스(7)였다 |
| 4 | `Pattern (1 * 1): 0` 형태로 크기와 값을 한 줄에 출력 | 값 "0"만으로는 패턴이 있는지 없는지 구분되지 않는다. 표로 옮기기도 쉽다 |
| 5 | 주석 정정 | `cblack[0..3]`은 Bayer 위치 순서가 아닌 색 번호 순서, `[4]`, `[5]`는 위치가 아닌 패턴 크기 |

**하지 않은 것과 이유**

- **패턴이 없을 때 `none` 출력**: 크기가 `(0 * 0)`으로 함께 찍혀서 "패턴 없음"이 출력만으로 구분된다. 분기를 추가하지 않았다.
- **폴더 순회 코드**: 11장 출력은 한 번만 하면 되는 작업이라, 프로그램은 한 장씩 받고 셸 반복문으로 돌렸다. 개발용 인자 방식을 그대로 유지한다.

## 질문하며 정리한 개념

### cblack\[0..3\]은 색 번호 순서

처음에는 "BGGR 각 위치의 기본값"으로 이해했다. 실제로는 `cam_mul`과 같은 색 번호 순서다.

| 인덱스 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 색 | R | G | B | G2 |

1단계에서는 `cblack[COLOR(r, c)]`로 꺼낸다. 위치 순서로 읽으면 BGGR 사진에서 R과 B의 기준값이 뒤바뀐다.

### 크기는 "추가 값이 있다"는 신호

"`[4]`, `[5]`는 그냥 크기인데 왜 확인하나"가 처음 의문이었다. Black Level을 담는 방식이 두 가지라서다.

| 방식 | 기준 | 값 위치 |
| --- | --- | --- |
| 색별 | 화소의 색 | `cblack[0..3]` |
| 위치 패턴 | 화소의 (행, 열) | 크기 `[4]` × `[5]`, 값 `[6]`부터 |

크기가 0 × 0이면 위치 패턴이 없고, 0이 아니면 `cblack[6]` 이후에 값이 더 있다. a0001이 실제로 이 경우였다. `cblack[0..3]`은 0 0 0 0이었지만, 값은 1×1 패턴의 `cblack[6]`에 들어 있었다.

패턴 크기는 Bayer 2×2와 같을 필요가 없다. 1×1이면 값 하나가 모든 화소에 적용되고, 위치 (r, c)의 값은 크기로 나눈 나머지로 찾는다.

```latex
\text{cblack}[6 + (r \bmod \text{cblack}[4]) \times \text{cblack}[5] + (c \bmod \text{cblack}[5])]
```

### 반복 범위를 메타데이터로 정한다

`6 + cblack[4] × cblack[5]`는 출력할 값이 아니라 반복문의 끝이다. a0001이면 6부터 7 직전까지, 즉 한 개만 출력된다. `cblack[6]`까지만 고정해 두면 2×2 패턴 사진에서 `[7..9]`를 놓친다. "카메라별 값을 코드에 박지 않는다"는 프로젝트 원칙을 값뿐 아니라 개수에도 적용한 것이다.

## raw-identify 대조와 11장 일괄 출력

### a0001 대조

```bash
sudo apt install libraw-bin
raw-identify -v data/a0001.dng
```

| 항목 | 내 출력 | raw-identify | 판정 |
| --- | --- | --- | --- |
| 카메라 | Nikon D70 | Camera: Nikon D70 | 일치 |
| 패턴 | BGGR | Filter pattern: BGGR… | 일치 |
| 크기 | 3040 × 2014 | Full size 3040 × 2014 | 일치 |
| Black Level | 0, 패턴 1×1: 0 | BlackLevelRepeatDim 1 x 1, cblack\[6 .. 6\]: 0 | 일치 |
| White Level | 4095 | Highlight linearity limits 4095 ×4 | 일치 |
| WB | 2.12891 1 1.54687 0 | As shot 2.12891 1 1.54687 0 | 일치 |

- **이 대조가 증명하는 것**: 내가 필드를 맞게 꺼냈다는 것. raw-identify도 LibRaw를 쓰므로 값 자체의 정답은 아니다. Black Level 0은 0-2에서 `raw_image` 최솟값으로 한 번 더 확인한다.
- **새로 알게 된 것**: `BlackLevelRepeatDim: 1 x 1`을 보고 위치 패턴 방식이 실제로 쓰인다는 것을 확인했다. 코드 변경 2의 계기다.
- **나중에 쓸 정보**: 권장 자르기 영역(Raw inset), camRGB → sRGB 행렬(5-1 CCM), D65 WB 계수(5-2), Baseline exposure −0.75(4단계 밝기 비교).

### 11장 일괄 출력

레포 최상단에서 실행했다. `tee`는 화면에 보여주면서 파일로도 저장한다.

```bash
cd build && make file_open && cd ..
for f in data/*.dng; do echo "===== $f"; ./build/file_open "$f"; echo; done | tee output/metadata_all.txt
```

- 파일명을 `echo`로 먼저 찍어, 어느 블록이 어느 사진인지 구분했다.
- `output/`은 git 제외 폴더라, README에 넣을 표는 따로 정리했다.
- 결과: a0001에서 세운 가정(12비트, Black 0, 여백 0)이 Canon 사진에서 모두 깨졌다. 한 장으로만 개발했다면 1단계 정규화와 0-2 인덱스가 다른 사진에서 틀렸을 것이다.
