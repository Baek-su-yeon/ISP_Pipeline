# 261004 DNG 열기와 메타데이터 출력

Oct 4, 2026 · @돌침대

환경 구축 이후, LibRaw로 FiveK DNG(a0001, Nikon D70)를 열고 unpack한 뒤 메타데이터를 출력하는 데까지 진행했다. 코드는 참고 자료를 보며 직접 짰고, 리뷰와 힌트로 고쳤다.

## 참고 자료와 LibRaw의 역할

코드는 직접 짜고, 아래 자료를 용도별로 나눠 본다. 남이 짠 코드를 이해하는 것보다 직접 짠 코드가 면접에서 설명하기 쉽다.

| 용도 | 자료 | 쓰는 법 |
| --- | --- | --- |
| 개념과 전체 흐름 | [Rob Sumner, Processing RAW Images in MATLAB](https://www.imatest.com/wp-content/uploads/2020/12/Rob_Sumner_RAWguide.pdf) | 단계별 원리. MATLAB이라 C++로 직접 옮겨야 함 |
| 할 일 체크리스트 | [Hacettepe BBM 444 과제 1](https://web.cs.hacettepe.edu.tr/~erkut/ain434-bbm444.s26/assgns/assgn1.pdf) (CMU 15-463 과제 각색), [NYU 과제](https://cs.nyu.edu/~fergus/teaching/comp_photo/assign1.pdf) | 코드 없이 단계별 구현·확인 사항만 제시 |
| LibRaw 사용법 | [C++ API](https://www.libraw.org/docs/API-CXX.html), [Data Structures](https://www.libraw.org/docs/API-datastruct.html) | 함수·필드 이름 찾기 |
| LibRaw 예제 | GitHub LibRaw `samples/` (raw-identify, 4channels) | 어떤 함수·필드를 쓰는지만 확인 |
| 정답 대조 | `sudo apt install libraw-bin` → `raw-identify -v` | 내 출력값 검증 |

### LibRaw를 쓰는 이유

- C++이라서 쓰는 게 아니다. Python 과제의 rawpy도 내부에서 LibRaw를 쓴다. C++에서 rawpy 역할을 하는 게 LibRaw다
- DNG는 공개 규격(TIFF 기반)이라 직접 읽을 수는 있다. 하지만 타일 구조, 무손실 JPEG 압축, 바이트 순서, 카메라별 예외까지 처리해야 해서 별도의 파일 파싱 프로젝트가 된다. 어려운 건 C++이 아니라 파일 형식이다
- 채널 분리는 LibRaw가 해주지 않는다. 4channels는 예제일 뿐이고, Bayer 배열과 패턴을 받아 직접 나눈다
- 경계: LibRaw는 파일 열기와 메타데이터 추출까지. Black Level 보정부터 감마까지는 직접 구현. 전체 처리 기능(dcraw\_process)은 비교용 기준 이미지에만 쓴다

### C++ API 문서 읽는 법

| 구역 | 볼 것 |
| --- | --- |
| 3. Methods Loading Data | `open_file()`, `unpack()` |
| 4. Auxiliary Functions | `COLOR(row, col)`, `strerror()`. `subtract_black()`은 직접 구현할 거라 참고만 |
| 5\~8 | dcraw 흉내 후처리·출력, datastream. 지금은 건너뜀 |

문서 본문은 unpack 결과가 `imgdata.image`에 들어간다고 하지만 오래된 설명이다. 같은 페이지 댓글에서 개발자가 자체 처리라면 `imgdata.rawdata.raw_image`를 쓰라고 답했다.

## cpp 파일 여러 개 빌드·디버깅

`main()`이 있는 cpp 하나가 실행 파일 하나가 된다. src에 파일을 만들기만 하면 CMake는 모르기 때문에, 파일마다 CMakeLists.txt에 등록해야 한다.

```cmake
add_executable(step1 src/step1.cpp)
target_link_libraries(step1 PRIVATE ${OpenCV_LIBS} PkgConfig::LIBRAW)
```

등록하지 않으면 VSCode Output에 "step1.cpp not found in compile\_commands.json" 메시지가 뜨고, 헤더 인식도 안 된다. 등록 후 `cmake ..`를 다시 돌리면 사라진다.

```bash
cd build
cmake ..
make step1     # 대상 하나만 빌드. make만 치면 전부 빌드
```

### 디버깅 (F5)

1. 디버그 정보를 넣어 빌드: `cmake -DCMAKE_BUILD_TYPE=Debug ..` 후 `make`
2. `.vscode/launch.json`에 실행 파일 위치를 알려줌

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Debug step1",
            "type": "cppdbg",
            "request": "launch",
            "program": "${workspaceFolder}/build/step1",
            "args": ["data/a0001.dng"],
            "cwd": "${workspaceFolder}",
            "MIMode": "gdb"
        }
    ]
}
```

- `cwd`를 레포 최상단으로 두면 `data/...` 상대 경로를 쓸 수 있다
- `args`로 실행 인자를 넘긴다
- 파일이 늘면 configurations에 블록을 추가하고 Run and Debug 드롭다운에서 고른다
- CMake Tools 익스텐션을 쓰면 상태바에서 대상 선택·빌드·디버그를 버튼으로 할 수 있어 launch.json이 없어도 된다

지금처럼 단계마다 main이 있는 파일을 두는 건 학습 단계용이다. 파이프라인을 이을 때는 단계를 함수로 빼서 별도 파일에 두고 main은 하나로 정리한다.

## DNG 열기 과정

처음엔 data 폴더를 순회하며 열었고, 실행 위치 문제를 해결한 뒤 실행 인자로 파일 하나를 받는 방식으로 바꿨다.

1. `LibRaw ip;`로 객체를 만들고 `ip.open_file()` 호출. open\_file은 `LibRaw::version()`처럼 클래스 이름으로 부르는 함수가 아니라 객체로 부르는 함수
2. 인자 타입이 `const char*`라 `std::string`은 `.c_str()`로 변환
3. `std::filesystem::directory_iterator`로 data 폴더를 돌며 각 파일을 열기 시도
4. 아무 출력 없이 끝남 → 원인은 실행 위치
5. 레포 최상단에서 `./build/step1`로 실행하자 성공(O 출력)
6. 개발 단계는 한 장씩 다루는 게 낫다고 판단해 `argv[1]`로 파일 경로를 받는 방식으로 변경
7. 인자 검사, 에러 메시지 출력, 실패 시 종료를 추가
8. `unpack()`까지 성공

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 실행해도 아무것도 안 나옴 | 상대 경로 `"data"`는 실행 위치 기준. build에서 실행하면 `build/data`를 찾아 `fs::exists`가 false. 그 경우 출력이 없게 짜여 조용히 종료 | 레포 최상단에서 `./build/step1` 실행. 모든 갈림길에 출력을 넣어 조용한 실패 방지 |
| 범위 기반 for문 `for (auto& x : argv)` 컴파일 에러 | 매개변수의 `char* argv[]`는 포인터로 바뀌어 크기 정보가 없음 | 인덱스 for문, 또는 `std::vector<std::string>(argv + 1, argv + argc)`로 변환 |
| for문이 `argv[0]`부터 돎 | `argv[0]`은 프로그램 이름 | 실제 인자는 `argv[1]`부터 |
| 인자 없이 실행 시 `basic_string: construction from null is not valid`, `Aborted (core dumped)` | 사용법은 출력했지만 `return 1`이 없어 다음 줄로 진행. `argv[1]`이 널 포인터라 string 생성 실패 | 사용법 출력과 `return 1`을 짝으로 |
| 파일을 잘 열어도 종료 코드 1 | 맨 마지막이 `return 1` | 실패 분기에 `return 1`, 끝은 `return 0` |
| 사용법 출력이 `./build/step1<input file>`로 붙음 | 문자열 앞 공백 누락 | `" <input file>"` |

`(core dumped)`는 프로그램이 죽는 순간 메모리 상태를 저장했다는 표시로, 비정상 종료를 뜻한다.

## 질문하며 정리한 C++ 개념

### 폴더 순회 vs 실행 인자로 받기

|  | 폴더 순회 | 인자로 경로 받기 |
| --- | --- | --- |
| 한 장씩 집중 개발 | 매번 전부 처리 | 원하는 한 장만 |
| 다른 사진으로 교체 | 폴더 내용 변경 | 실행 명령만 변경 |
| 디버깅 | 몇 번째 파일 문제인지 찾아야 함 | 문제 파일 하나로 재현 |

개발은 인자로 한 장씩, 10장 전체 처리는 폴더 순회로 나눈다. 폴더 순회 시에는 `fs::path`의 확장자 함수로 `.dng`만 거른다.

### argc, argv 관례

```cpp
int main(int argc, char* argv[]) {
    if (argc < 2) {
        std::cerr << "Usage: " << argv[0] << " <input file>" << std::endl;
        return 1;
    }
    std::string input = argv[1];
    // 본 작업
    return 0;
}
```

- `argc`는 인자 개수, `argv[0]`은 프로그램 이름, 실제 인자는 `argv[1]`부터
- 개수 검사는 맨 앞에서. 뒤 코드가 "인자는 있다"고 믿고 짤 수 있음
- 정상 결과는 `cout`, 에러·안내는 `cerr`. 결과를 파일로 저장할 때 섞이지 않음
- 사용법에 `argv[0]`을 쓰면 실행 파일 이름이 바뀌어도 맞게 출력
- 받자마자 `std::string`이나 `fs::path`로 변환
- 옵션이 많아지면 getopt, CLI11, cxxopts 같은 라이브러리를 씀

### 배열이 포인터로 바뀌는 규칙 (decay)

함수 매개변수의 `char* argv[]`는 배열처럼 보이지만 `char**` 포인터로 바뀐다. 포인터는 시작 위치만 알고 개수를 몰라서 범위 기반 for문을 쓸 수 없다. 개수가 `argc`로 따로 넘어오는 이유다. 메타데이터 출력에서 `cam_mul` 배열을 그대로 출력했을 때 주소가 나온 것도 같은 규칙 때문이다.

### 에러 처리

```cpp
int ret = ip.open_file(input.c_str());
if (ret != LIBRAW_SUCCESS) {
    std::cerr << LibRaw::strerror(ret) << std::endl;
    return 1;
}
```

- LibRaw 함수는 성공 시 0, 실패 시 에러 번호를 반환
- `LIBRAW_SUCCESS`는 0에 이름을 붙인 상수. 의도가 잘 보임
- 음수는 LibRaw 내부 에러(형식 미지원, 파일 손상), 양수는 시스템 에러
- `LibRaw::strerror()`는 에러 번호를 영어 설명으로 변환. 표준에도 `std::strerror`가 있어, `using namespace std;`를 쓰지 않은 덕분에 헷갈리지 않음

### early return

실패하면 그 자리에서 이유를 출력하고 `return 1`. 여기까지 왔다면 성공이므로 `else`가 필요 없다. 단계가 늘어도 들여쓰기가 깊어지지 않고 위에서 아래로 읽힌다. 실패를 출력만 하고 진행하면, 열지도 못한 파일을 unpack하려는 식으로 다음 단계가 이어진다.

### 종료 코드

main의 반환값은 운영체제에 전달된다. 0은 성공, 0이 아니면 실패. 실행 직후 `echo $?`로 확인한다. 여러 사진을 스크립트로 처리할 때 성공 여부 판단에 쓴다. `return 1` 대신 `<cstdlib>`의 `EXIT_FAILURE`를 쓰기도 한다.

## 메타데이터 출력

open\_file이 채운 구조체에서 값을 꺼내 출력했다. 첫 실행에서 WB 계수가 주소로 나오는 등 네 군데를 고쳤다.

### open\_datastream을 따로 부르지 않는 이유

open\_file은 파일 경로로 데이터 스트림을 만든 뒤 open\_datastream을 대신 호출하는 포장 함수다. open\_file이 성공하면 `imgdata.idata`, `sizes`, `color`, `other`, `thumbnail`이 이미 채워져 있다. open\_datastream을 직접 부르는 건 네트워크·메모리 같은 파일이 아닌 입력을 쓸 때다. 일부 값(Black Level 등)은 unpack에서 계산·보정되므로 메타데이터 출력은 unpack 뒤에 한다.

### 꺼낸 필드

| 구조체 | 필드 | 의미 |
| --- | --- | --- |
| `imgdata.idata` | `make`, `model` | 제조사, 모델 |
|  | `filters` | Bayer 배치를 비트로 압축한 숫자 |
|  | `cdesc` | 색 이름 문자열 (보통 "RGBG") |
| `imgdata.sizes` | `raw_height`, `raw_width` | 여백 포함 raw 전체 크기 |
|  | `height`, `width` | 여백 뺀 실제 이미지 크기 |
|  | `top_margin`, `left_margin` | 여백 |
| `imgdata.color` | `black` | 공통 Black Level |
|  | `cblack[0..3]` | 채널별 추가 Black Level |
|  | `maximum` | White Level |
|  | `cam_mul[4]` | 카메라 기록 WB 계수 |

### 첫 실행 결과 (a0001.dng)

```
Camera manufacturer: Nikon
Camera model: D70
filters: 505290270
Raw Height: 2014, Width: 3040
Real Height: 2014, Width: 3040
Margin top: 0, left: 0
Black level: 0
White level: 4095
WB coefficient: 0x7ffef85497b8
```

### 고친 점

| 항목 | 문제 | 수정 |
| --- | --- | --- |
| WB 계수 | `cam_mul`은 원소 4개 배열이라 그대로 출력하면 주소가 나옴 (배열→포인터 규칙) | 원소 4개를 반복문으로 출력 |
| filters | 값은 맞지만 숫자라 RGGB인지 알 수 없음 | 2×2 위치에 `COLOR(r, c)`를 부르고 그 번호로 `cdesc`의 글자를 출력 |
| 실제 크기 | `iheight`, `iwidth`는 후처리 출력용 크기라 옵션에 따라 달라짐 | `height`, `width`로 변경. 이 사진은 여백 0이라 값이 같았을 뿐 |
| Black Level | `black`만 출력. 채널별 값이 따로 있을 수 있음 | `cblack[0..3]` 추가 출력. raw-identify로 대조 |

### 읽어낸 정보

- White Level 4095 = 2¹² − 1. 화소값이 12비트(0\~4095). 1단계 정규화에서 이 값으로 나눔
- 크기 3040×2014는 LibRaw 포럼의 같은 파일 정보(ActiveArea 3040×2014)와 일치
- Black Level 0은 D70이 실제로 0일 수 있어 raw-identify로 확인 예정
- Bayer 패턴, WB 계수 실제 값은 수정 코드 실행 후 확인 예정

## 현재 코드 (src/file\_open.cpp)

지적 사항을 반영한 버전이다. 실행: 레포 최상단에서 `./build/file_open data/a0001.dng`

```cpp
// dng 파일 열기
#include <libraw/libraw.h>
#include <iostream>
#include <string>

int main (int argc, char* argv[]) {
    if (argc < 2) {
        // 입력 경로 제대로 쳤는지 확인
        std::cerr << "Usage: " << argv[0] << " <input file>" << std::endl;
        return 1;
    }

    std::string input = argv[1];

    LibRaw ip; // 객체 생성
    int ret = ip.open_file(input.c_str()); // 파일명 char로 받으니까 변형
    if (ret != LIBRAW_SUCCESS) {
        std::cerr << LibRaw::strerror(ret) << std::endl;
        return 1;
    }
    std::cout << "file open" << std::endl;

    ret = ip.unpack();
    if (ret != LIBRAW_SUCCESS) {
        std::cerr << LibRaw::strerror(ret) << std::endl;
        return 1;
    }
    std::cout << "success unpack" << std::endl;

    std::cout << "Image idata Info" << std::endl;
    std::cout << "Camera manufacturer: " << ip.imgdata.idata.make << std::endl;
    std::cout << "Camera model: " << ip.imgdata.idata.model << std::endl;

    // 2x2 위치별 색을 글자로 출력
    std::cout << "Bayer pattern: ";
    for (int r = 0; r < 2; r++) {
        for (int c = 0; c < 2; c++) {
            std::cout << ip.imgdata.idata.cdesc[ip.COLOR(r, c)];
        }
    }
    std::cout << std::endl;
    std::cout << "-------------------------------------------------------" << std::endl;

    std::cout << "Image Size Info" << std::endl;
    std::cout << "Raw Height: " << ip.imgdata.sizes.raw_height << ", Width: " << ip.imgdata.sizes.raw_width << std::endl;
    std::cout << "Real Height: " << ip.imgdata.sizes.height << ", Width: " << ip.imgdata.sizes.width << std::endl;
    std::cout << "Margin top: " << ip.imgdata.sizes.top_margin << ", left: " << ip.imgdata.sizes.left_margin << std::endl;
    std::cout << "-------------------------------------------------------" << std::endl;

    std::cout << "Image Color Info" << std::endl;
    std::cout << "Black level: " << ip.imgdata.color.black << std::endl;

    // 채널별 추가 Black Level
    std::cout << "Per-channel black: ";
    for (int i = 0; i < 4; i++) {
        std::cout << ip.imgdata.color.cblack[i] << " ";
    }
    std::cout << std::endl;

    std::cout << "White level: " << ip.imgdata.color.maximum << std::endl;

    // 배열 주소 대신 원소 4개 출력
    std::cout << "WB coefficient: ";
    for (int i = 0; i < 4; i++) {
        std::cout << ip.imgdata.color.cam_mul[i] << " ";
    }
    std::cout << std::endl;

    return 0;
}
```
