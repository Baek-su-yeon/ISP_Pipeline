# 261008 4단계 Gamma 회고

Oct 8–9, 2026 · @돌침대

## 요약

Demosaic 결과(선형 RGB, 0~1)에 sRGB 감마를 적용해, 처음으로 모니터에서 제대로 보이는 컬러 이미지를 만들었다. 단순 거듭제곱(`x^(1/2.2)`)도 같이 만들어 두 곡선을 비교했다. 마지막으로 LibRaw와 비교 조건을 맞춰 결과를 대조해, 8비트 기준 최대 1 차이를 확인하고 4단계를 마쳤다.

- **곡선**: sRGB 구간식 채택. 단순 거듭제곱은 비교용으로 남김
- **검증**: 기대값 5개 일치 → 입력 기준으로 고른 화소 대조(직선·거듭제곱 구간) → 구간별 개수 합 = H × W × 3
- **LibRaw 비교**: 조건 맞춤 시 선형 16비트 최대 차이 2(a0005 G만 21), sRGB 8비트 최대 차이 1 (가장자리 2화소 제외)
- **가장 많이 배운 것**: 비선형 단계는 평균으로 검증할 수 없다. 입력값 기준으로 화소를 골라 기대값과 대조해야 한다.
- **코드**: 당시 `src/test.cpp` → 리팩토링 후 `src/gamma.cpp`, `src/verify.cpp`, `src/libraw_ref.cpp`

## 시작 전 정리

### 감마를 하는 이유

| 이유 | 내용 |
| --- | --- |
| 디스플레이 특성 상쇄 | CRT는 밝기 ∝ 전압^2.2. 선형 값을 그대로 보내면 어둡게 보이므로 역수 곡선으로 미리 휘어 둔다. 3단계 결과가 어두웠던 이유 |
| 8비트 단계 배분 | 사람 눈은 어두운 쪽 차이에 민감. 감마로 저장하면 256단계 중 많은 부분이 어두운 구간에 배정된다. 선형 8비트는 어두운 쪽 단계가 부족해 밴딩이 생긴다 |

### 두 곡선과 기대값

```
단순 거듭제곱:  y = x^(1/2.2)
sRGB 구간식:    x ≤ 0.0031308 → y = 12.92 × x
                x > 0.0031308 → y = 1.055 × x^(1/2.4) − 0.055
```

| 입력 x | x^(1/2.2) | sRGB | 8비트 (2.2 / sRGB) |
| --- | --- | --- | --- |
| 0.001 | 0.0433 | 0.0129 (직선) | 11 / 3 |
| 0.0031308 | 0.0727 | 0.04045 (양쪽 식 모두) | 19 / 10 |
| 0.18 | 0.4587 | 0.4614 | 117 / 118 |
| 0.5 | 0.7297 | 0.7354 | 186 / 188 |
| 1.0 | 1.0 | 1.0 | 255 / 255 |

- 어두운 구간에서 단순 거듭제곱이 약 3배 밝다. 0 근처 기울기가 무한대라 노이즈도 그만큼 키운다.
- 중간 이상 밝기에서는 8비트로 1~2 차이뿐이다.

**결정: sRGB 구간식**
- LibRaw 기준 이미지와 비교할 때 조건을 맞출 수 있다.
- 5단계 CCM이 sRGB 색공간으로 바꾸는 행렬이라 감마도 sRGB가 일관된다.

**구조 결정**: 진행 순서상 CCM이 5단계지만, CCM은 선형 값에 곱해야 한다. 그래서 감마는 독립 단계 함수로 두고, 5단계에서 Demosaic과 감마 사이에 CCM을 끼워 넣기로 했다.

## 질문하며 정리한 개념

### `x^(1/2.2)`은 어디서 왔나

CRT 모니터는 입력 전압 V와 밝기 L이 `L ∝ V^2.2`였다. 전압 0.5를 주면 밝기는 0.22다. 그래서 저장할 때 `x^(1/2.2)`로 미리 휘어 두면 화면에서 `(x^(1/2.2))^2.2 = x`로 원래 빛의 양이 된다. LCD는 원래 이런 특성이 없지만 일부러 2.2를 흉내 낸다. 2.2는 물리 상수가 아니라 관례값이다(예전 Mac은 1.8).

### sRGB 계수의 의미

| 계수 | 의미 |
| --- | --- |
| `1/2.4` | 거듭제곱 지수 |
| `0.055` | 곡선을 아래로 내려 0 근처에서 직선과 만나게 함 |
| `1.055` | 내린 만큼 키워 x = 1일 때 1 (흰색은 흰색) |
| `12.92` | 직선 구간 기울기. 경계에서 두 식 값이 같도록 정함 |
| `0.0031308` | 두 식이 만나는 경계 |

0.055만큼 내리면 곡선이 덜 휘므로 지수를 2.4로 잡아 전체 모양을 2.2와 비슷하게 맞췄다. 원래 설계는 경계에서 값과 기울기가 모두 이어지게 계산했고, 표준에 넣으며 반올림해 아주 미세한 차이가 남는다.

### 직선 구간을 두는 이유

`x^(1/2.2)`은 0 근처 기울기가 무한대다. 0.0001 → 약 0.015, 0.001 → 약 0.043처럼 아주 작은 입력 변화가 크게 증폭되어, 어두운 곳의 센서 노이즈가 커진다. sRGB는 이 구간을 기울기 12.92 직선으로 바꿔 증폭을 제한한다.

### 비선형 단계는 평균으로 검증할 수 없다

3단계는 "출력 평균 = 입력 평균"으로 검증했다. 감마는 `mean(gamma(x)) ≠ gamma(mean(x))`라 같은 방법이 안 된다. 화소 몇 개를 골라 "입력 → 기대 출력"을 대조한다.

### 검증 화소는 입력 기준으로 고른다

감마 결과로 정렬해 고르면, 틀린 코드가 만든 값으로 검증 대상을 고르는 순환 논리가 된다. 분기 조건이 틀려도 "출력이 작은 화소"는 여전히 골라진다. 입력값으로 구간을 나눠 골라야 분기 오류를 잡는다.

### LibRaw의 Black·maximum 처리

`dcraw_process` 뒤에는 `black = 0`, `maximum = WL − black`으로 바뀐다. Black을 먼저 빼고 최댓값도 같이 줄인 상태로 저장하기 때문이다. 그래서 비교할 때는 처리 전(`unpack` 직후)과 처리 후 값을 둘 다 봐야 한다. WB 이득(`pre_mul`)도 처리 후에는 G = 1로 정규화된 값이라 내 `gains`와 같아진다.

## 배운 점과 다음 단계

**배운 점**

- 비선형 단계는 평균 대신 "입력 기준 화소 대조"로 검증한다.
- 값 하나짜리 함수를 먼저 기대값으로 맞추면, 이미지 단계에서 문제가 생겨도 식은 의심하지 않아도 된다.
- 같은 감마 차이라도 사진에 따라 영향이 다르다(a0001 직선 구간 23개, a0005 2.7%). 숫자로 세어야 판단할 수 있다.
- 외부 기준과 비교할 때는 "무엇을 같게 할지"를 먼저 정한다. 조건을 안 맞추면 차이의 원인을 가를 수 없다.
- 남은 차이를 그냥 두지 않고 식으로 설명한다(G_R 분모 3270 vs 3271 → 21).
- 저장 직전 BGR 변환은 헬퍼 하나로 모은다. 같은 실수를 두 번 했다.
